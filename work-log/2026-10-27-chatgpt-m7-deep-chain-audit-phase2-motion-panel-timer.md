## Concurrency/negative/error/recovery review

- JS `transitionGateRef`, pending mode and readiness waiter prevent ordinary mode re-entry; incoming trees are inert until commit; native `presentation_guard` and token-locked `FOCUS_MODE_RASTER` prevent two raster owners. A failed outgoing `CapturePreview` produces an error without a published native commit.
- B explicitly captures `sourceTaskId`, calls `assertMotionV4TaskIdentity` before and after native animation and before forward renderer publish, while exempting a genuine rollback from that forward predicate. Layout creation also demands equal task ID and semantic title/clock text; negative temporary loading/Time's Up/scroll conditions use deterministic fallback.
- Optional clean-plate capture errors are intentionally caught and native fallback remains operational; they do **not** mean an operator-visible display glitch cannot occur. A stale lease token/invalid stage/layout/geometry rejects the staging command. Native owner rolls back Window snapshot/region when needed. A raster finish only releases on committed target and validated final capture; watchdog recovery is bounded *attempt*, not a physical DWM guarantee.
- **Explicit unproven race:** a live task/clock projection may update between last forward identity check and final async `finishFocusSurfaceModeRaster` capture/release; neither the checked static guards nor pure JS scalar tests prove its pixels coherent in that interleaving. Concrete next semantic test: controlled projection advance precisely at `renderer.commit`→`renderer.release-request`, verify first new authoritative clock/title and release crop have same task identity; only change code if an executable test actually fails.
- Native timer placement during motion is save-suppressed and saved/recovered outside lease; upcoming PR431 placement/inset merge with A/B touches the *same* `src-tauri/src/lib.rs` state owner. Combining branches without conflict review and resulting-source visual tests can undo the current first-hidden-Timer Panel anchor/16-DIP inset, or B native sprite-layout assumptions. Check selected-monitor topology, recovery and renderer paint after integration rather than assuming independent passes compose.
- 500ms B animation extends exposure to environment changes versus 250ms baseline, but that is *not* quantified failure evidence. Reduced1ms often commits faster than nominal screenshot sampling; one-frame DWM artifacts cannot be inferred absent.
- Expected keyboard/focus and an actual task/session ledger are cross-owned by M6, Win32 shortcuts M8 and session persistence M9.
