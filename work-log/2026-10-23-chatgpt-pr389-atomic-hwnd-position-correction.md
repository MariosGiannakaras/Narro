## Root-cause analysis and correction scope

- In the accepted PR389 design, `src-tauri/src/focus_webview.rs::set_physical_position` previously moved the Tauri Focus HWND by `.set_position()` and **then** independently relocated the owned raster popup via `focus_layered_raster::sync_owner_position`. Between those two Win32 position updates, DWM can observe unrelated content from the persistent WebView and transient layer at different desktop origins. This sequencing is **proven in code**; its sufficiency as the sole visual cause is still a **hypothesis** pending physical retest.
- Corrected the shared finite-raster movement boundary on existing branch/PR only. `src-tauri/src/focus_layered_raster.rs` exposes `move_owner_and_popup` and issues `BeginDeferWindowPos(2) → DeferWindowPos(owner) → DeferWindowPos(popup) → EndDeferWindowPos` on the Focus UI thread, preserving both sizes, Z-order and nonactivation; owner/popup identity, command results and resulting physical positions are checked. `src-tauri/src/focus_webview.rs` now uses this batch if the transient popup exists, preserves Tauri `.set_position()` when no popup exists, and still requests WebView2 `NotifyParentWindowPositionChanged` on success and on an ambiguous native failure before rollback.
- Added native Windows test creating genuine owner+owned popup HWNDs and asserting the pair moves to the exact same destination without resizing; reversed/unowned pair is rejected without moving either HWND. Updated the required `scripts/test-ui-focus-surface-transition.mjs` contract to check real production routing and the ordered Win32 API batch, guard paths, no sequential SetWindowPos. No new test gate or weakened test.
- Existing projection, timer/domain authority, persistence, React active/preparing state, animation duration, 340×700/110/300 geometry, rollback/watchdog, main webview, approved Spectrum Core Create/Edit List picker/upload/218 icons, and user AppData are unchanged. OS Win32 deferred positioning API documented by Microsoft; API contracts support an implementation but **do not prove visual DWM behavior**.
