## Acquisition, analysis and verdict records

- Batch compatible checks with minimal repeated setup. Original full-resolution video/actual PTS plus source/EXE/PID/HWND/action chronology owns temporal claims. UIA/logs/screenshots are corroboration, not a replacement for motion evidence. Audio claims need actual audio observation; silent capture is not sound PASS.
- Necessary intermediate probes, capture-health checks, input fixes and method changes are allowed. If a drag yields zero displacement, no movement test occurred; establish real movement or request only the required human input and leave that claim NOT RUN. Do not replay stationary transitions as differing-position proof.
- Quiet CPU/memory measurement must use its dedicated non-recording protocol; do not let OBS/analysis work contaminate an idle-performance claim.
- Freeze useful segments and manifests, then analyze complete relevant intervals before source patches. Preserve actual failure context and bookmark timestamps. Avoid Git updates inside a continuous capture; publish the safe boundary checkpoint afterward.
- Per case record: requirement ID; source/run/artifact/EXE identity; actual environment; expected/observed; action and timestamp/PTS; PASS/FAIL/INCONCLUSIVE/NOT RUN; evidence path; limitations; owner and next proof. A surface appearing in video is not exercised coverage.
- A confirmed failure returns to the application source owner for cause-led correction, regression and only invalidated revalidation. Two separately corrected CI-validated builds physically failing the same criterion require the existing architectural reassessment; two recorders of one failure do not meet that threshold.
- Raw generated evidence stays outside tracked Git. Publish compact sanitized manifests/findings and a named consumer/retirement condition for any required large attachment. Preserve all original Blitzit media. Capture no unrelated user desktop/content when avoidable; do not publish whole user profiles or logs unrelated to the case.
