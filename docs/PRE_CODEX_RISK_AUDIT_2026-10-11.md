## Concrete prephysical risk found: two unhandled listener registration rejections

In both `src/TimedAlertSoundRuntime.tsx` and `src/TimedAlertFlashRuntime.tsx`, the effect installs `connectTimedAlertEffects` and has a `.then(unlisten => ...)` success continuation **without `.catch`**. `src/timedAlertApi.ts` returns the Promise from `@tauri-apps/api/event.listen`. Therefore, if registering that listener rejects, there is a JavaScript unhandled Promise rejection and that consumer has no registered event handler, no runtime diagnostic/error state or recoverable subscription strategy.

This is a **source-proven missing negative branch**; it does NOT show that a listener actually failed on current Windows. Existing fast tests `scripts/test-timed-alert-sound-runtime.mjs` and `scripts/test-timed-alert-flash-runtime.mjs` verify static wiring, sound owner and DOM accessibility/visual contracts, but do **not** inject rejection into listener connection or exercise recovery.

**Disposition: NEEDS_REGRESSION_FIRST**, not a license to substitute speculative retries or alter UI styling. Recommended next nonphysical source slice, if user wants robustness remediation: add a focused deterministic rejected-`listen` regression first and a narrow explicit error-handling strategy with bounded recovery/diagnostics consistent with existing no-renderer-polling invariant.
