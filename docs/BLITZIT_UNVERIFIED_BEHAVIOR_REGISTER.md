## Purpose and exact rules

The user explicitly directed Narro to **implement the in-scope product even where source interactions are incompletely recorded**, make defensible, testable, local-first choices rather than inventing Blitzit behavior, and keep **every source-uncertain choice inspectable later when the user personally examines Blitzit**. The earlier color-picker mistake illustrates why unobserved behavior must never be called source-confirmed.

This register is a **review index**, not another roadmap, shadow TODO, or proof of actual Blitzit parity. The authoritative implementation status is `TODO.md`/`HANDOFF.md` and every finding's actual disposition is `docs/AUDIT_IMPLEMENTATION_CROSSWALK.md`. Code changes remain in milestone order, independently validated through exact-head Windows CI, and physically reviewed together later. Never mark a source question resolved because Narro's own test passed. No unknown source dialog/menu action or numerical formula may be attributed to Blitzit without direct supporting evidence.

**Engineering treatment of unknown behavior:** consume canonical Pass-3 and calibrated system first; where source remains indeterminate and an in-scope feature must operate, implement the safest deterministic Windows/accessibility/local-only rule fitting adjacent evidence, with real state ownership and regression coverage. Record it as `NARRO_INFERRED` or `USER_APPROVED`, never as `BLITZIT_CONFIRMED`. When changing an authoritative metric, recurrence/lane contract, destructive command, break accounting or timer ledger would amount to inventing fundamental semantics, preserve proven data integrity and record `SOURCE_FORMULA_UNKNOWN`/`PRODUCT_DECISION_REQUIRED` until a defensible independent definition exists. Avoid inert controls masquerading as actions.

**Future M11 check:** the last column gives a concrete observation target if the user later explicitly starts M11. Until that instruction, collect no live Blitzit data, do not plan/start M11, change no M11 milestone denominator and do not mark these questions PASS. When M11 actually starts, route these checks into its *complete up-front* capture matrix, observing the M11 capture→freeze→analysis embargo.
