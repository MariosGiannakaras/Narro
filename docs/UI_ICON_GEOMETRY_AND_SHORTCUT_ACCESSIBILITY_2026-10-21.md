## Confirmed layout problems and constrained repairs

1. **Reports Overview + Sessions calendars:** both import `reportsOverview.css` and share `.reports-overview__calendar header` with `grid-template-columns: 22px 22px minmax(0,1fr) 22px 22px`. Each of the four arrows is an `ActionIcon` (default 16px). Base App buttons add `padding: var(--space-2) var(--space-3)` (8px top/bottom, 12px left/right). Without a specific override, the button's min-content/intrinsic width is **at least 16px SVG + 24px horizontal padding + borders**, exceeding a 22px grid cell and causing inconsistent centering/overflow into nearby arrow/title tracks. Scoped `width/height:22px`, `min-width/min-height:0`, `box-sizing:border-box`, `padding:0`, `display:inline-grid;place-items:center` correct only the four navigation arrows without changing the date grid/presets/handlers. The exact 22px value comes from the **existing grid** (not a new guess).
2. **Focus Panel header quick actions:** existing `.focus-panel__quick-controls button` reserved 32px minimum yet inherited 4px+8px internal padding around a 16px SVG, causing actual preferred content width to exceed the minimum. Retained the already specified 32x32px geometry and set `box-sizing:border-box;display:inline-grid;place-items:center;padding:0`. No changes to action routing, hover, focus-visible ring or disabled state.
3. **Reports Sessions close + inline Save:** the UI uses a 28x30px Save check icon and 32x32px modal Close buttons, with reset padding but default inline baseline alignment. Added grid centering *inside existing dimensions* in `reportsSessions.css`. Backdrop, dialog positioning, tabs, keyboard trap, session commits remain unchanged.
4. **Reports navigation / Export PDF + Search Back:** icon followed by short label formerly shared inline text baseline; corrected `display:inline-flex;align-items:center` and reused existing spacing tokens `--space-1/2` to obtain a consistent visible text/icon relationship across Sessions/Overview/Search. No new font sizes, glyphs, spacing tokens or theme palette introduced.
5. **Windows Shortcuts spoken chord:** three global and seven in-app shortcut rows show visually correct individual `<kbd aria-hidden>` keycaps, but the full key sequence relied on `aria-label` on a generic `<span>`, not guaranteed to expose an accessible name. Kept visible keycaps untouched; placed a single ordinary real-text `<span className="windows-shortcuts__accessible-chord">{row.chord}</span>` per row, visually hidden with locally scoped screen-reader-safe CSS (`clip-path:inset(50%)`, not `display:none`), without duplicate announcement from the decorative `kbd` elements.
6. **Windows Shortcuts registration concurrency:** `WindowsShortcutSettingsPanel.change(kind,enabled)` previously guarded with `pendingKind` React state only. Two same-event-turn callbacks can both pass the old state and send overlapping native OS shortcut (un)registrations, allowing stale responses to overwrite the latest settings snapshot. Added synchronous `useRef` admission acquired before native `setGlobalShortcutEnabled` and released in `finally` even after native reject/authoritative refresh. UI pending/retry/error handling, actual persisted state and OS registration authority unchanged.
