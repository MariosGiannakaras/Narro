## Actual production code ownership and call order

**Expand:** `FloatingTimerFoundation.requestExpanded(true)` synchronously flushes `expanded=true`, sets `prepainting`, then calls `waitForPresentedFrame()` (two JavaScript `requestAnimationFrame` callbacks in `src/presentationFrame.ts`). It then invokes `FocusSurfaceCoordinator.requestTimerExpanded(true)`, whose `commitPreparedFocusPresentation` uses `waitForTargetReady: async () => {}` and a direct `focus_surface_apply_presentation` Tauri IPC, finally publishes `timerExpanded`. In `src-tauri/src/lib.rs`, `apply_focus_surface_presentation_internal` takes a native presentation mutex, snapshots rollback state and calls `apply_timer_native`. Expansion moves the compact host to the clamped safe origin, calls `timer_region::apply_without_redraw(window, expanded.region())`, and sets native attributes. The native region uses `SetWindowRgn(...,FALSE)`. **No incoming pixel-content receipt, raster hold, or composited-generation verification occurs between the rAF barrier and revealing the extended native region.** Two rAFs say that React/JS presented tasks, **not** that the GPU-backed WebView2 surface handed over a fresh composited 300px frame.

**Collapse:** the same React component first animates contraction, flushes `expanded=false`, awaits double rAF, invokes `focus_surface_capture_compact_frame` to obtain a WebView2 `CapturePreview` PNG; then `apply_timer_native` installs a *finite 500ms child raster* via `focus_frame_hold::begin`, contracts native region with `apply_without_redraw`, keeps the safe origin, and `hold.commit()` releases Rust RAII cleanup to the child watchdog. CapturePreview is geometry-checked, but there is still **no guarantee that the captured compact frame belongs to the requested renderer generation** (and old backing remains elsewhere). The same failure appears with reduced motion, so just shortening or extending animation intervals cannot be relied on.

**Panel↔Timer mode change** is a different, more carefully bounded path: `focus_surface_prepare_mode_raster` snapshots outgoing WebView2 pixels and creates an 8s watchdog-protected child raster; the coordinator prepares target DOM and drives `focus_surface_animate_presentation` with source/target token and a finite geometry animation; `focus_surface_finish_mode_raster` captures final pixels, validates target geometry and replaces the raster bitmap before release. Even here a matching HWND/size/token does not prove content freshness. Do not conflate mode raster tokens with a composited target-frame receipt.

**Safety constraints from prior physical history:** forced Win32 region redraw (`SetWindowRgn(...,TRUE)`) generated white/blank frames in an older exact Windows session. PR #208 deliberately introduced no-redraw Timer swaps. Never try an arbitrary redraw flag flip, WebView HWND resize/recreate/hide, blind rAF loops/delays, blocking COM/UI thread, unbounded capture retries, or an unrelated CSS camouflage patch. Native timer state/persistence remains the authoritative domain source, and the renderer uses the existing one persistent WebView2/HWND.
