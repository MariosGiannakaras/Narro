## Decision and evidence boundary

- Keep Tauri 2, React, WebView2, authoritative Rust timer/session state, and SQLite. `main` remains a separate application window. Use **one** persistent `focusSurface` HWND/WebView for Focus Panel and both Floating Timer states; remove the experimental persistent `floatingTimer` WebView from the resulting implementation.
- The supplied VE-003 recording establishes a roughly 0.27-second *visible* Panel/Timer geometry transformation. It does not reveal Blitzit's internal window count or component architecture. Dynamic component toggling/conditional rendering inside one Focus WebView is a Narro implementation decision, not a confirmed Blitzit fact. "Single-Activity Architecture" is only an analogy: Narro still has a separate `main` window, while Focus Panel and Timer share one persistent Focus host.
- The old single-WebView implementation hid and resized its HWND and repeatedly failed exact-build physical Gate 7 with white/blank frames. The now-closed, unmerged PR #191 fixed-host **second** Timer WebView avoided the earlier white resize frames but still left 0.07–0.10 seconds of Panel/Timer overlap on exact build `4e4960b` and added about 95 MiB working set in the recorded comparison. Neither is accepted as a Gate 7 solution. See the existing immutable M7 work logs.
- This is technically feasible to implement with the current stack: PR #191 already uses Win32 `SetWindowRgn` to clip a fixed-size Timer HWND. Applying DPI-aware clipping to the single Focus HWND, including its width, avoids routine WebView resize and eliminates two-Focus-window overlap by construction. Physical visual success remains unproven.

## Target composition

| Presentation | One `focusSurface` host | Visible native region at 100% reference scale | React presentation |
| --- | --- | --- | --- |
| Focus Panel | Fixed maximum host, nominally 340 × 700 logical px | 340 × 700 | Panel |
| Compact Timer | Same host and WebView, no mode resize | 340 × 110 | Compact Timer |
| Expanded Timer | Same host and WebView, no mode resize | 340 × 300 | Expanded Timer |

The **340 px width is the validated product geometry** used by the M6 Focus Panel CSS/visual contracts and M7 Timer. The older 400 px native Panel width came from the M1 diagnostic/window scaffold and is not the product-visible target. Use a fixed nominal 340 × 700 Focus host so ordinary Panel/Timer/expand changes vary the native visible-region height (700 / 110 / 300) and position rather than the WebView width. Compute physical region dimensions from the target monitor scale. Adapt the host only when display/work-area constraints or DPI/topology changes genuinely require it.
