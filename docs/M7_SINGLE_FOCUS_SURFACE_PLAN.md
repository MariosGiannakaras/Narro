# M7 single Focus surface implementation plan

Status: **approved implementation direction, not implemented or validated** (2026-09-29). This document is the next-chat handoff for the M7 Panel/Timer transition. The user explicitly deferred all tests, builds, CI, app launches, recordings, and physical acceptance checks until the implementation is complete and they say to proceed with testing.

## Decision and evidence boundary

- Keep Tauri 2, React, WebView2, authoritative Rust timer/session state, and SQLite. `main` remains a separate application window. Use **one** persistent `focusSurface` HWND/WebView for Focus Panel and both Floating Timer states; remove the experimental persistent `floatingTimer` WebView from the resulting implementation.
- The supplied VE-003 recording establishes a roughly 0.27-second *visible* Panel/Timer geometry transformation. It does not reveal Blitzit's internal window count or component architecture. Conditional rendering within one Focus WebView is a Narro implementation decision, not a confirmed Blitzit fact. `Single-Activity Architecture` is an analogy, not the Windows implementation model.
- The old single-WebView implementation hid and resized its HWND and repeatedly failed exact-build physical Gate 7 with white/blank frames. The unmerged PR #191 fixed-host **second** Timer WebView avoids the earlier white resize frames but still leaves 0.07–0.10 seconds of Panel/Timer overlap on exact build `4e4960b` and adds about 95 MiB working set in the recorded comparison. Neither is accepted as a Gate 7 solution. See the existing immutable M7 work logs.
- This is technically feasible to implement with the current stack: PR #191 already uses Win32 `SetWindowRgn` to clip a fixed-size Timer HWND. Applying DPI-aware clipping to the single Focus HWND, including its width, avoids routine WebView resize and eliminates two-Focus-window overlap by construction. Physical visual success remains unproven.

## Target composition

| Presentation | One `focusSurface` host | Visible native region at 100% reference scale | React presentation |
| --- | --- | --- | --- |
| Focus Panel | Fixed maximum host, nominally 400 × 700 logical px | 400 × 700 | Panel |
| Compact Timer | Same host and WebView, no mode resize | 340 × 110 | Compact Timer |
| Expanded Timer | Same host and WebView, no mode resize | 340 × 300 | Expanded Timer |

The nominal dimensions follow existing Narro M7 geometry; compute the physical region from the current monitor scale. Adapt the host only when display/work-area constraints or DPI/topology changes genuinely require it, not on ordinary Panel↔Timer or expand/collapse transitions. CSS Timer layout must use the 340 px visible width, not the 400 px host viewport, and must not expose scrollbars or interactive content outside the clipped region.

## Implementation order for the next chat

1. **Continue from the current unmerged PR #191 checkout, or a child implementation branch of it.** Use validated `main` as the behavioral/source baseline, and replace the experimental split composition rather than layering another window over it. Retain useful Win32 region/DPI and safe-position code; remove the second WebView and its cross-window switching protocol. Keep PR #191 unmerged until later authorized validation and preserve unrelated working-tree files.
2. **Native host and clipping:** configure a single `focusSurface` maximum-size host in `src-tauri/tauri.conf.json`. Generalize `src-tauri/src/timer_region.rs` (rename if useful) to apply Panel, compact Timer, and expanded Timer rectangular regions with DPI-aware **width and height**. Keep HWND/WebView size stable during ordinary mode and expand/collapse transitions. Remove `floatingTimer` window creation and references only after replacement paths exist.
3. **Position and mode authority:** consolidate `src-tauri/src/lib.rs` mode/expand commands on `focusSurface`. Retain Rust presentation authority and serialized requests. Rework `src-tauri/src/floating_placement.rs` and display-change reconciliation to save/clamp the **visible clipped rectangle**, because the invisible 400 × 700 host may extend below or beyond a work-area edge when a compact Timer is placed there. Recompute the region and safe position on DPI/topology change. Preserve Panel monitor/side preference, Timer drag position, topmost/taskbar rules, and safe expand-near-bottom ordering (move before reveal; clip before restoring compact origin).
4. **One React coordinator:** combine the Panel and Timer presentations under the `focus.html` entry (`src/focus.tsx`, `src/focusPanelWindow.tsx`, `src/floatingTimerWindow.tsx`, `src/FloatingTimerFoundation.tsx`). Use one serialized mode controller and shared authoritative projection. Prepare the incoming subtree in the same WebView while the outgoing view remains visible; keep inactive controls inert and absent from keyboard/accessibility navigation. Avoid `display:none` as the preparation mechanism because it cannot prepaint target pixels. Do not duplicate timer/session subscriptions or let rendering start, stop, reset, or advance a session.
5. **Visible transition:** coordinate target content readiness, native region/position/topmost/taskbar update, and a short finite content motion in one sequence. Preserve the source's continuous geometry character where practical, with roughly 0.27 s as a calibration target. Do not animate WebView/HWND size or drive native geometry from a high-frequency JavaScript loop. A bounded native region/position animation is permissible if needed for continuity, but it must end in the exact native mode geometry and never own domain completion. Respect reduced motion. On any failure, restore prior visible region, position, native attributes, React presentation, and mode without changing task/session state.
6. **Retire the experimental split path:** remove obsolete `timer.html`, `floatingTimer` capability/config entries, cross-WebView ready/query events, `src/persistentFocusWindowTransition.ts` usage, and stale visual-hold/prewarm paths that no longer have a purpose. Keep working shared action components and source-derived UI states. Do not perform unrelated refactors or change timer/session/persistence behavior.
7. **Stop at implementation complete.** Update `HANDOFF.md`, `TODO.md`, `STATUS.md`, and the audit crosswalk with what was implemented and what is still unverified. Do **not** run tests, builds, CI, launch the app, perform visual capture, or claim Gate 7/12 PASS. Do not push a source commit if that would trigger CI before the user authorizes testing. Wait for the user's explicit instruction to begin the later validation phase.
